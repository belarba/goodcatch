# Good Catch redesign — design

Date: 2026-09-24. Branch: `redesign`.

## Goals

1. Make it obvious there are two daily games, and open straight into play.
2. Replace emoji with pixel sprites (style A: coloured, dark 1px outline).
3. Fix the usability gaps from the prototype, starting with first-player feedback:
   "I couldn't get the net back to the boat."
4. Show where the player stands for the day: their best/lowest vs the day's
   best/lowest possible score (solver). No backend.
5. English and Portuguese.

## Non-goals

- No backend, no global leaderboard (planned later — see "Ranking source").
- No change to map generation (`genNet`, `genLine`, seeds, `EPOCH`). Today's maps stay identical.
- Not a copy of enclose.horse; it is a tone reference only (game-first, minimal chrome, pixel).

## Constraints

- Site stays one static `index.html`, no build, no runtime dependencies.
- Dev-only tooling may live in `tools/` (Node), never loaded by the page.
- Test at ~400px and desktop.

## Screen (approved mockup "layout B, game first")

Top to bottom:

1. Header: `?` (help) · title + `#N · Mon D` · `≡` (menu: language, practice map).
2. Game switcher: compact two-segment control, 16px pixel icon + name + the player's
   best of the day (`▲19`) per game.
3. Board, full width.
4. Meta row: countdown (`Net left: N` / `Line left: N`) and live `Catch: +12`.
5. One-line hint (contextual; see Interaction).
6. Buttons: Undo · Clear · primary (Haul net / Reel in).
7. Points strip: the 9 sprites with their points, always visible. Tapping a sprite
   highlights every animal of that kind on the board.

After committing a try, a result panel replaces the board: big score, verdict,
"Today's best possible +25 · lowest −16", a bar showing how close the player's best is
to the optimum, the player's best/lowest, and buttons Try again · Share day.

Help modal opens automatically on first visit (`goodcatch:seenHelp`), otherwise via `?`.
It holds the full rules of both games. Long rule text leaves the main screen.

## Visual identity

- Fonts: Pixelify Sans (titles, numbers, counters, buttons) + Figtree (prose). Drop
  Bricolage Grotesque and JetBrains Mono.
- Sprites: 12×12 string maps in the script, rendered once to data URLs with an
  auto-generated dark outline. Set: 9 species, boat, rock, net icon, line icon.
  Drawn at an integer scale derived from cell size (`image-rendering: pixelated`).
- Protected animals: red pixel frame instead of the dashed circle.
- Net sea: subtle checker + deterministic pixel wave ticks. Line sea: stepped depth
  bands + textured sand floor.
- Board stays a DOM grid with the SVG path overlay; only cell contents change.

## Interaction

Both games: click-by-click and drag behave the same.

Net:
- Countdown of squares left.
- After every step, BFS from the net's end to the boat, treating rocks and the net as
  walls except the boat itself. The shortest return path is drawn dashed orange.
- States: normal → warning (squares left == return distance: orange counter,
  hint "Head back now") → ready (loop closed).
- A step is blocked, with a short cell shake and hint, when it hits a rock
  ("Rock in the way"), crosses the net ("Can't cross your own net"), or would leave
  no way back ("Not enough net to get back"). Blocking dead ends removes no valid
  closed net.
- Tapping the boat closes the loop (fixed in 720387e).

Line:
- Countdown of squares left; crossing an animal shows a floating "−2".
- Ready when the line touches the seabed.

## Ranking source

Single seam: `dailyReference(game, date) → {best, worst, exact}`. The UI only talks to
it, so a future backend (percentiles, leaderboard) replaces this function only.

- Line: exact DFS at load (spike: 20–167 ms in Node across 5 days).
- Net: exact search is 3–39 s per day in Node (spike, 7 days), too slow for phones.
  So `NET_REF = {"YYYY-MM-DD":[best,worst],…}` is embedded in `index.html` between
  `// @net-ref-start` / `// @net-ref-end`, generated by `tools/solve-net.mjs`.
  The tool reads the generator from `index.html` between `// @gen-start` /
  `// @gen-end` (no duplicated logic), verifies each optimum against `evaluate`,
  and rewrites the table.
- Date not in the table, or practice map: capped search (2 s) in an inline Web Worker,
  labelled "best known" (`exact: false`).

## Language

`STR.en` / `STR.pt`, `t(key)`. Default from `navigator.language` (`pt*` → pt, else en);
override in the menu, stored in `goodcatch:lang`. `<html lang>` follows. Species names
and verdicts are translated.

## Share

Text in the UI language, e.g.
`Good Catch #24 · Net ▲19/25 ▼−10/−16 · Line ▲14/19 ▼−20/−24 · goodcatch.fish`.

## Storage

Unchanged: `goodcatch:<date>:<game>` → `{best, worst, tries}`. New: `goodcatch:lang`,
`goodcatch:seenHelp`. Existing `goodcatch:tab` keeps selecting the game. All wrapped in try/catch.

## Verification

- No test framework. `tools/solve-net.mjs` checks the solver against the game's `evaluate`.
- Browser QA with real clicks at 400px and desktop, both languages; includes the
  click-by-click net closing flow and the blocked-step messages.
